# ADR-0002: Canonical versioned configuration

- Status: Accepted
- Date: 2026-09-24
- Owners: Rovia maintainers

## Context

Using an engine's JSON as the application's persisted model would couple the UI, subscription importer, routing editor, and future engines. It would make a second engine a collection of engine-specific conditionals.

## Decision

Rovia persists a canonical, engine-independent model. Every persisted root object has a `schemaVersion`. Engine-specific JSON is generated by an `EngineConfigCompiler` and is not part of the public domain model.

Credentials are represented by `SecretReference`. Secret values are resolved only at the platform boundary and are never serialized into `AppConfig`, fixtures, traces, or diagnostics.

The first schema uses camelCase JSON fields and deterministic coding key strategies. Unknown or unsupported fields are rejected or handled through an explicit migration policy rather than silently discarded.

## Consequences

- The UI and routing debugger can operate without an engine.
- Android can implement the same contracts against the same schemas and fixtures.
- Schema migrations become explicit and testable.
- The canonical model is more verbose than native engine JSON, but remains auditable and stable.

## Validation

Canonical model tests must cover schema version persistence, round trips, invalid input, and secret-reference-only persistence.
