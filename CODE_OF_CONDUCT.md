# Code of Conduct

## The standard

Rovia contributors must make project spaces welcoming, professional, and safe.

Be respectful. Assume good faith, and assume competence: a question that looks basic
usually means the documentation failed to explain something, which is a real defect
worth reporting. Do not harass participants, publish private personal information,
discriminate, or intentionally disrupt technical work.

Disagreement about a design decision is the point of an ADR. Argue the decision, not
the person who wrote it, and assume the other person has read the constraint you have
not.

## Security research

Good-faith security research is welcome, and it is not a Code of Conduct matter.
Vulnerabilities go through the private process in [`SECURITY.md`](SECURITY.md), never
through a public issue or a pull request, and applicable law applies as it would
anywhere else.

A researcher who follows the disclosure process, does not access data beyond what is
needed to demonstrate the issue, does not degrade the service or build for others, and
gives reasonable time to fix, is acting in good faith.

## Reporting

Report a conduct concern to the maintainer through the same private channel used for
security reports, or through GitHub's private reporting. Do not post it in an issue,
a discussion, or a pull request.

If a report concerns the maintainer, and the maintainer is the only person who can act
on it, that is a limit of this project's size rather than a reason to stay silent —
raise it through the same channel and it will be handled as best a one-person project
can, which is usually by stepping back.

## Enforcement

Maintainers may edit or remove contributions that violate this policy, and may restrict
participation when necessary to protect the community or the project infrastructure.
Enforcement is proportionate: a first report normally means a conversation, and a
pattern means the participation is restricted.

The project is currently maintained by one person, so "maintainers" means that person.
That is a real limitation and it is stated here rather than implied away.

## Scope

This applies in every project space: the repository, issues, pull requests,
discussions, and any commit content.
